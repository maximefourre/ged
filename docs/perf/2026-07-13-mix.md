# Perf campaign — profile `mix` (2026-07-13)

Reference load: 1 000 documents, sizes 50 KB – 5 MB, run in both modes.

## Conditions

- Command: `bin/perf-upload --profile mix --mode both` (6 upload threads)
- Stack: isolated worktree Docker stack (`bin/worktree-stack up`), production
  Rails env, Solid Queue in Puma (`SOLID_QUEUE_IN_PUMA=true`,
  `JOB_CONCURRENCY=1`, worker threads 3, `RAILS_MAX_THREADS` default 3),
  Thruster in front of Puma
- Host: Apple M4 Max, 14 cores, 36 GB RAM; Docker VM 14 CPUs / ~16 GB
- Verification: every 202'd request polled to a terminal state; document
  count re-read from the API filtered on the run's `perf_run` tag

## Reading

- Async accepts ~3× faster than sync (7 375 vs 2 492 docs/min) because the
  202 path only writes the row + staging file; the actual storage then drains
  at ~2 900 docs/min through the single Solid Queue worker
  (`JOB_CONCURRENCY=1`, 3 threads) — that worker is the async bottleneck, as
  expected.
- Sync throughput is bounded by Puma's 3 request threads doing the
  Active Storage write inline (p50 140 ms/doc ≈ 6 threads × ~7 docs/s).
- Zero HTTP errors, zero failed requests, API count matches in both modes.
