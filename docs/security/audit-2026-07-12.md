# GED — Security Audit (2026-07-12)

**Scope:** full application (bearer/JWT auth, department authorization, async
upload + callback, file storage/download, admin UI, config, dependencies).
**Baseline commit:** `23ce792`.
**Method:** read-only source review across three focus areas (auth/authz;
upload/callback/files; admin/config/deps).

Overall the codebase is clean and defensively written; the classic Rails
vulnerability classes are correctly handled. The actionable findings are
concentrated in one SSRF, an optional audience check, and transport/header
hardening.

## Strong controls confirmed (do not regress)

- JWT: RS256 pinned (no `alg:none` / HS256 confusion), `iss` + `exp` + `nbf`
  verified; JWKS fails closed on a cold cache and rate-limits unknown-`kid`
  refreshes.
- Every `/api/v1` action is authenticated **and** department-authorized; no
  `skip_before_action` anywhere.
- Admin: CSRF protection on (ERB + `ActionController::Base`), login brute-force
  rate-limited, no public registration.
- Strong params everywhere (no `permit!`); parameterized SQL and jsonb binds
  (`sanitize_sql_like`, named `?` operator).
- UUID primary keys on documents/upload_requests (no enumerable IDOR); staging
  path derived from a server UUID (no traversal); downloads stream from disk with
  `attachment` disposition.
- Secrets not committed (`.env`, `config/master.key` gitignored); the dev
  OAuth provider generates its RSA key at runtime.
- CI runs `brakeman` + `bundler-audit` + `importmap audit`; dependencies current;
  Docker runs as non-root.

## This-branch remediation

Finding **#1 (SSRF)** is fixed on `feat/read-write-permissions` via
`CallbackUrlPolicy` (syntactic 422 at request time + DNS-resolved refusal at
delivery time). Findings #2–#7 and the LOW items are recorded here for a later
hardening pass; #2 and #5 belong to the real-IdP cutover checklist already noted
in `AGENTS.md`.
